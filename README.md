# Make Your PR Humanoid

在 Qoder 和 VS Code 中评阅 Git 分支、记录行范围意见，并把评阅任务导出给你使用的 Agent。

## 安装

从 [GitHub Releases](https://github.com/fanqin-zeng/make-your-pr-humanoid-plugin/releases) 下载与你的编辑器对应的 VSIX。在扩展面板的菜单中选择「从 VSIX 安装」。需要本机 Git，并在受信任的工作区使用。VS Code 需要 1.106 或更新版本。Qoder 安装包已在 Qoder CN IDE 验证。

## 分支评阅

在活动栏打开「分支评阅」，选择仓库、目标分支和来源分支。Diff 左侧是两分支的 PR 合并基点，右侧是所选版本的来源快照。检出来源分支时，快照会收录已跟踪文件的工作树改动、暂存的新增文件和已回传的新增文件。

原生 Diff 默认自动换行。已有的 `diffEditor.wordWrap` 设置优先。

目标分支默认使用本地的 `upstream/HEAD` 所指分支，其次是 `upstream/main` 或 `upstream/master`。没有本地上游主分支时，使用 `origin/main` 或 `origin/master`。也可以在下拉列表手动指定目标。「刷新比较」读取本地 Git 引用。

「拉取上游更新」获取 `upstream` 的远端默认分支，用来源分支的已提交内容做合并预检。遇到冲突时，沿上游第一父提交链回退到最近能无冲突合并的提交，将其作为本地上游跟踪引用和评阅目标，并提示下一条冲突提交与涉及的文件。来源分支、暂存区和工作树保持原样。此按钮需要 Git 2.38 或更新版本。

代码或 PR 基点变化时生成新版本，编号为 `v0001`、`v0002` 等。通过「评阅版本」切换。未修改的行范围会携带意见和回复进入新版本。行范围内的内容被改动时，可在历史版本查看原意见和回复。

在本机用 Qoder 和 VS Code 打开同一个工作区并选择相同的仓库和分支时，两边共享版本、已读标记、意见、回复和澄清。升级后，用原先填写过意见的编辑器打开对应的分支评阅一次，旧记录会自动迁移。同一快照中的意见会合并，数据库保存在仓库的本地 Git 元数据目录中。

右侧「评阅详情」上部显示变更摘要和修改澄清，下部集中管理行意见和回复，默认占比分别为 20% 和 80%。在 Diff 任一侧选中行范围，通过右栏表单提交意见。点击行号可定位原文。

底部「全部评论」按「版本 → 文件 → 评论 → 回复」显示同一分支组合的评阅历史，最新版本排在顶部。面板工具栏可以一键展开或折叠。点击评论或回复会切换到对应的评阅版本并定位原文。

在「变更文件」右上角可以展开或折叠全部目录，也可以切换文件树和平铺显示。右键树中的文件、目录或已打开的评阅页签，可以复制对应名称、绝对路径和仓库相对路径。文件行的悬停按钮会打开当前检出的工作树文件。

Agent 回传的变更摘要说明文件的修改目的。每个文件的摘要句数上限为新增、删除行数之和除以 500 后向上取整。已有版本可以从已保存的修改澄清提取摘要。

## 导出与回传

1. 写完意见后，勾选本轮授权的操作。选中「自动 push」会选中「自动 commit」和「自动修改」。取消前置项会清除依赖它的选项。
2. 输入或浏览保存目录，点击「导出更新需求prompt」，把生成的 Markdown 文档交给你选择的 Agent。文档包含本轮意见、确切的 Git 快照、操作授权和结果文件格式。开启自动修改时，此前已回复但尚未落实的意见也会导出。
3. Agent 在文档指定位置保存结果后，扩展将回复写回对应意见，并更新澄清和评阅版本。通知里的「查看版本」会打开对应的评阅。关闭编辑器期间回传的结果会在下次打开原工作区时读取。

「导出修改澄清需求prompt」会列出当前评阅版本里缺少澄清的 diff 行范围。新增行按新侧行号计算，删除行按旧侧行号计算，替换行需要覆盖两侧。已有澄清和新回传的范围合并后必须覆盖所有文本变更行，扩展才会接受「完成」状态。普通上下文行和没有文本行的文件变更无需覆盖。该入口只请求澄清，自动修改、提交和推送开关仅用于「导出更新需求prompt」。

两个导出入口都提供「打开文件夹」和「复制文件目录」。复制的是 Markdown 文件所在的目录。

默认复用工作区里已有的评阅目录。两种目录同时存在时，优先使用 `.vscode-review/requests/`。工作区没有评阅目录时，VS Code 首次导出会创建 `.vscode-review/requests/`，Qoder 会创建 `.qoder-review/requests/`。也可以在保存目录栏指定其他位置。

扩展按工作区、仓库和分支组合保存记录。「导入 HTML 评阅的修改澄清」命令可以复用 Git 快照相同的 `*.clarifications.json` 文件。

## 本地打包

运行 `python package.py`，两个编辑器的 VSIX 会生成到 `dist/`。
